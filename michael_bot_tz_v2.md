## 1. Загальний опис

### 1.1 Мета системи

Michael Bot — Telegram-чатбот (асистент Майкл), який автономно веде природну розмову з потенційним клієнтом: дізнається про бізнес, виявляє біль, рахує скільки коштує ручна робота, презентує релевантний кейс Олександра і записує на онлайн-зустріч через Fineko. Усі діалоги зберігаються в БД і відображаються в адмін-панелі — як чат-бульбашки, так і візуальний timeline бізнес-процесу.

### 1.2 Стек

| Компонент | Технологія |
|---|---|
| Сервер | PHP 8.1+ (shared hosting, cPanel) |
| БД | MySQL 8 |
| Чатбот | Telegram Bot API (webhook) |
| AI-мозок | Claude API — Haiku 4.5 з промпт-кешуванням |
| Запис на зустріч | Fineko API (tasks.fineko.space/mcp) |
| Адмін-панель | PHP + Bootstrap 5 |
| Сповіщення власнику | Telegram Bot API |

## 2. Головна ідея: живий діалог

Майкл — не лінійний скрипт. Це повноцінний AI-асистент, який веде природну розмову.

**Ключові вимоги:**
- Клієнт може запитати будь-що по ходу — бот відповідає коротко і м'яко повертається до теми автоматизації
- Бот знає контекст усієї розмови: не перепитує одне й те саме
- Воронка проходить природньо, без жорстких переходів між STEP-ами
- Бот має чіткий сценарій (воронку), але не боїться відхилятися від теми розмови
- Ніяких фраз типу "Я не можу відповісти на це питання" — тільки живі відповіді

---

## 3. Сценарій розмови (воронка)

> Майкл веде розмову, орієнтуючись на поточний `stage` ліда. Переходи між STEP-ами визначаються самим Claude на основі контексту — не жорсткими умовами в коді.

### STEP 1 — Вітання
**Тригер:** /start або перше повідомлення.

**Майкл пише:**
> "Привіт! Я Майкл, AI-асистент Олександра Мацука. Олександр — спеціаліст з автоматизації та оптимізації бізнес-процесів. Він допомагає бізнесам прибрати ручний хаос і нарешті зробити так, щоб операційка не з'їдала весь час. Скажіть, чим ви займаєтесь?"

### STEP 2 — Дізнатися і знайти біль
Майкл слухає, задає уточнюючі питання. Якщо клієнт запитує щось стороннє — відповідає коротко і повертає до теми. Визначає сферу (`business_type`) і ключовий біль.

### STEP 3 — Калькулятор втраченого часу
Майкл задає 3–5 питань:
- Скільки людей у команді?
- Які процеси найбільше 'їдять' час?
- Скільки годин на тиждень витрачається?
- Яка приблизна вартість години роботи?

**Формула:** год/тиж × 4 × грн/год = прихованих витрат/міс

Результат зберігається в `hours_lost`, `money_lost`.

### STEP 4 — Презентація кейсу
Claude вибирає найрелевантніший кейс з бази (за `business_type` і `keywords`) і подає природньо:

> "О, цікаво! В Олександра був дуже схожий кейс. [Короткий опис ситуації клієнта]. Після автоматизації [результат з цифрами]. Схожа картина виходить і у вас — орієнтовно [money_lost] грн/міс. Хотіли б обговорити з Олександром як це вирішити?"

### STEP 5 — Запис через Fineko
Якщо клієнт погоджується, Майкл перевіряє вільні слоти через Fineko API і показує варіанти (Inline keyboard у Telegram). Після вибору:
1. Створює задачу в Fineko: "Зустріч: [ім'я] / [сфера] / [час]"
2. Надсилає клієнту підтвердження з датою, часом та посиланням
3. Надсилає Олександру Telegram-сповіщення з резюме ліда

## 4. Живий діалог: технічна реалізація

### 4.1 Як працює контекст

Claude API не зберігає стан між запитами. При кожному повідомленні від клієнта `webhook.php`:

1. Зберігає нове повідомлення в `messages` (role=user)
2. Витягує всю історію `messages` цього ліда з БД
3. Формує запит: `system_prompt` + `[{role, content}, ...вся_історія]`
4. Надсилає в Claude API, отримує відповідь
5. Зберігає відповідь в `messages` (role=assistant)
6. Надсилає відповідь клієнту через Telegram

> **Кешування:** System prompt кешується (cache_control: ephemeral) — 90% знижка на повторні запити. Якщо діалог > 30 повідомлень — перші стискаються до AI-резюме і зберігаються у `pain_summary`.

### 4.2 Структура system prompt

System prompt — це "мозок" Майкла. Передається при кожному запиті і містить:

- **Роль:** "Ти Майкл, дружній AI-асистент Олександра Мацука. Розмовляєш природньо, без шаблонів."
- **Поточний stage** ліда (передається динамічно з БД)
- **Кейси Олександра** з бази (топ-3 за релевантністю до business_type)
- **Правила воронки:** коли і як переходити між STEP-ами
- **Правила живої розмови:** відповідати на питання клієнта, потім м'яко повертати до теми
- **Спеціальний тег:** `[SHOW_SLOTS]` — коли показати Inline keyboard зі слотами Fineko
- **Заборони:** не обговорювати конкретну вартість послуг, не бути роботом

## 7. Структура БД (MySQL)

### 7.1 Таблиця `leads`

```sql
CREATE TABLE leads (
  id INT PRIMARY KEY AUTO_INCREMENT,
  telegram_id BIGINT UNIQUE NOT NULL,
  username VARCHAR(100) NULL,
  first_name VARCHAR(100),
  phone VARCHAR(20) NULL,
  business_type VARCHAR(100),        -- сфера: меблі, e-commerce, NGO...
  pain_summary TEXT,                 -- AI-резюме болю
  hours_lost DECIMAL(5,1),           -- годин/міс (калькулятор)
  money_lost DECIMAL(10,2),          -- грн/міс
  matched_case_id INT NULL,          -- FK -> cases.id
  stage ENUM('new','qualified','cta_sent','booked','rejected','archived') DEFAULT 'new',
  followup_count TINYINT DEFAULT 0,
  last_message_at DATETIME,
  meeting_at DATETIME NULL,
  fineko_task_id VARCHAR(100) NULL,  -- ID задачі у Fineko
  created_at DATETIME DEFAULT NOW()
);
```

### 7.2 Таблиця `messages`

```sql
CREATE TABLE messages (
  id INT PRIMARY KEY AUTO_INCREMENT,
  lead_id INT NOT NULL,
  role ENUM('user','assistant') NOT NULL,
  content TEXT NOT NULL,
  stage_at_send VARCHAR(50),         -- stage на момент відправки
  api_call_id VARCHAR(100) NULL,     -- ID запиту до Claude API
  created_at DATETIME DEFAULT NOW(),
  FOREIGN KEY (lead_id) REFERENCES leads(id)
);
```

### 7.3 Таблиця `cases`

```sql
CREATE TABLE cases (
  id INT PRIMARY KEY AUTO_INCREMENT,
  category ENUM('automation','consulting') NOT NULL,
  title VARCHAR(255),
  business_type VARCHAR(100),        -- для матчингу
  keywords TEXT,                     -- ключові слова через кому
  problem TEXT,                      -- опис проблеми (1-3 речення)
  solution TEXT,                     -- що було зроблено
  result TEXT,                       -- результат з цифрами
  hours_saved DECIMAL(5,1) NULL,
  money_saved DECIMAL(10,2) NULL,
  is_active TINYINT(1) DEFAULT 1
);
```

### 7.4 Таблиця `process_log` (для timeline в адмін-панелі)

```sql
CREATE TABLE process_log (
  id INT PRIMARY KEY AUTO_INCREMENT,
  lead_id INT NOT NULL,
  event_type ENUM(
    'msg_received',
    'claude_called',
    'case_matched',
    'slots_shown',
    'fineko_created',
    'notification_sent',
    'followup_sent',
    'stage_changed',
    'error'
  ) NOT NULL,
  event_data JSON NULL,              -- деталі: {case_id: 3, stage: 'qualified'}
  duration_ms INT NULL,              -- час виконання API-запиту
  created_at DATETIME DEFAULT NOW(),
  FOREIGN KEY (lead_id) REFERENCES leads(id)
);
```

### 7.5 Таблиця `settings` (key-value конфіг)

```sql

  `key` VARCHAR(100) PRIMARY KEY,
```

## 9. Інтеграція Fineko

### 9.1 Що робить бот через Fineko

- Отримує список задач на найближчі 7 днів → визначає зайняті слоти
- Пропонує клієнту вільні слоти (Inline keyboard)
- Після вибору: створює задачу-зустріч у Fineko
- Зберігає `fineko_task_id` в `leads`

### 9.2 Алгоритм вибору слотів

1. GET задачі з Fineko на 7 робочих днів вперед
2. Визначити зайняті інтервали
3. Знайти вільні слоти в межах робочих годин (з `settings`)
4. Показати перші `slots_to_show` варіантів як Inline keyboard

### 9.3 Задача після підтвердження

```
Назва:              Зустріч: [first_name] / [business_type]
Очікуваний результат: [pain_summary]
Дата:               вибраний слот
Тривалість:         slot_duration_min хвилин
```

## 10. Архітектура (PHP)

### 10.1 Файлова структура

```
/michael-bot/
├── webhook.php          # точка входу Telegram (перевіряє secret token)
├── cron.php             # follow-up серія (щохвилини через cPanel)
├── config.php           # ключі API, константи (поза public_html!)
├── api/
│   ├── claude.php       # Claude API wrapper (збирає context, парсить теги)
│   ├── telegram.php     # sendMessage, sendInlineKeyboard, sendNotification
│   └── fineko.php       # get_slots, create_task
├── models/
│   ├── Lead.php
│   ├── Message.php
│   ├── Case.php
│   └── ProcessLog.php
└── admin/
    ├── index.php        # Dashboard
    ├── leads.php        # Список + деталь (Чат + Timeline)
    ├── cases.php        # CRUD кейсів
    ├── settings.php
    └── analytics.php
```

### 10.2 Покрокова логіка webhook.php

1. Перевірити `X-Telegram-Bot-Api-Secret-Token`
2. Знайти або створити `lead` за `telegram_id`, оновити `last_message_at`
3. Зберегти message (role=user), залогувати `msg_received` в `process_log`
4. Витягти всю історію `messages` ліда
5. Залогувати `claude_called`, надіслати запит до Claude API
6. Отримати відповідь, залогувати `duration_ms`
7. Якщо відповідь містить `[SHOW_SLOTS]` → запит до Fineko, показати кнопки, залогувати `slots_shown`
8. Якщо callback від вибору слоту → `create_task` в Fineko, підтвердження клієнту, сповіщення власнику
9. Зберегти відповідь (role=assistant), надіслати клієнту
10. Оновити `stage` в `leads`, залогувати `stage_changed` якщо змінився

- Webhook secret token — перевірка `X-Telegram-Bot-Api-Secret-Token` при кожному запиті
- Адмін-панель — session-based авторизація (login/password)
- `config.php` — поза `public_html` або `.htaccess: Deny from all`
- Всі SQL — prepared statements (PDO)
- Rate limiting: max 10 повідомлень/хв від одного `telegram_id`
- HTTPS обов'язково (Telegram вимагає для webhook)

## 12. CRON (Follow-up)

**Налаштування в cPanel:**
```
* * * * * /usr/bin/php /home/user/michael-bot/cron.php >> /tmp/michael_cron.log 2>&1
```

**Логіка cron.php:**
1. SELECT ліди WHERE `stage` NOT IN ('booked', 'rejected', 'archived')
2. Для кожного: `(NOW - last_message_at)` в хвилинах
3. Якщо досягнуто інтервал і `followup_count` < 3 → згенерувати follow-up через Claude API з контекстом ліда
4. Надіслати, залогувати `followup_sent`, `++followup_count`
5. Якщо `followup_count` = 3 і минув `delay_archive` → `stage = archived` + сповіщення Олександру
