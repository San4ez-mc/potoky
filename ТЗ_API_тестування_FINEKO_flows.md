## 2. Що потрібно зробити

### 2.1 Додати `create_edge` до MCP

Інструмент є в UI платформи, але не доступний через MCP API. Потрібно його експортувати.

**Контракт:**

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `botId` | string | ✅ | UUID бота |
| `source` | string | ✅ | ID ноди-джерела |
| `target` | string | ✅ | ID ноди-приймача |
| `animated` | boolean | ❌ | Анімація лінії (default: `false`) |
| `label` | string | ❌ | Підпис на edge |

**Повертає:**
```json
{ "created": { "id": "edge_xxx", "source": "...", "target": "..." } }
```

---

### 2.2 Додати методи тестових сесій

П'ять нових методів для програмної симуляції Telegram-діалогу з ботом — без реального Telegram.

---

#### `start_test_session`

Створює ізольовану тестову сесію для бота.

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `botId` | string | ✅ | UUID бота |
| `userId` | string | ❌ | Ідентифікатор тестового юзера (default: `"test_user"`) |

**Повертає:**
```json
{ "sessionId": "sess_xxx", "botId": "...", "userId": "...", "createdAt": "..." }
```

---

#### `send_test_message`

Надсилає повідомлення в активну тестову сесію та повертає відповідь бота.

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `sessionId` | string | ✅ | ID сесії з `start_test_session` |
| `message` | string | ✅ | Текст повідомлення від юзера |

**Повертає:**
```json
{
  "sessionId": "...",
  "userMessage": "...",
  "botResponse": "...",
  "savedFiles": ["cashflow_articles", "pl_articles"],
  "timestamp": "..."
}
```

> `savedFiles` — масив назв файлів, якщо в цьому кроці спрацювала `saveFile` нода.

---

#### `get_session_logs`

Повертає повний лог діалогу сесії.

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `sessionId` | string | ✅ | ID сесії |
| `limit` | number | ❌ | Кількість останніх повідомлень (default: всі) |

**Повертає:**
```json
{
  "sessionId": "...",
  "messages": [
    { "role": "user", "text": "...", "timestamp": "..." },
    { "role": "bot", "text": "...", "timestamp": "..." }
  ]
}
```

---

#### `end_test_session`

Закриває сесію та очищує тимчасові дані.

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `sessionId` | string | ✅ | ID сесії |

**Повертає:**
```json
{ "sessionId": "...", "ended": true, "duration_seconds": 42 }
```

---

#### `get_errors`

Повертає помилки виконання для бота або по всьому проєкту.

| Параметр | Тип | Обов'язковий | Опис |
|----------|-----|:---:|------|
| `botId` | string | ❌ | Фільтр по боту (якщо не передано — всі боти) |
| `limit` | number | ❌ | Кількість останніх помилок (default: 20) |

**Повертає:**
```json
{
  "errors": [
    { "botId": "...", "sessionId": "...", "nodeId": "...", "error": "...", "timestamp": "..." }
  ]
}
```

## 3. Вимоги до ізоляції тестових сесій

- Тестові сесії **не** зберігають файли в реальне сховище студента
- `saveFile` ноди в тестовій сесії зберігають дані в тимчасову пам'ять сесії — повертаються в полі `savedFiles`
- `loadFile` ноди в тестовій сесії читають з тимчасового сховища поточної сесії
- Після `end_test_session` всі тимчасові дані видаляються
- Claude API виклики в тестовій сесії — реальні (не мок), але ізольовані від продакшн-логів

## 5. Критерії якості діалогу

Для кожного бота перевіряємо:

| Критерій | Очікуваний результат |
|----------|---------------------|
| Діалог завершується | Бот доходить до `saveFile` і `msg_done` без зависання |
| Не питає вже відоме | Якщо контекст є в `loadFile` — не перепитує ті самі дані |
| Реакція на підтвердження | «Так, підтверджую» → одразу генерує output, не задає нових питань |
| `saveFile` спрацьовує | В `savedFiles` є очікувані файли (напр. `cashflow_articles`, `pl_articles`) |
| Відсутність помилок | `get_errors` не повертає помилок для бота після сесії |
