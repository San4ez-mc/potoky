## BUG-001 · `get_connector` не повертає збережені екземпляри

**Статус:** Відкритий  
**Пріоритет:** Середній  
**Виявлено при:** Перебудова Bot 1.1 Onboarding

**Опис:**  
`get_connector` і `list_connectors` повертають тільки *визначення типу* конектора — схему, опис, іконку. Але не повертають збережені екземпляри де вже налаштовані ключі. Через це неможливо через MCP/API вибрати існуючий налаштований конектор і підключити його до ноди.

**Очікувана поведінка:**  
У відповіді `get_connector` додати масив `instances` — збережені екземпляри цього конектора поточного акаунту. Секретні значення не передавати — тільки label і id.

**Пропонована зміна відповіді `get_connector`:**
```json
{
  "id": "ad7582d3-...",
  "name": "Claude Haiku",
  "type": "claude_haiku",
  "schema": { "..." },
  "instances": [
    {
      "id": "inst_abc123",
      "label": "Haiku — Finance Course",
      "has_keys": true,
      "keys_configured": ["api_key"]
    }
  ]
}
```

## BUG-003 · `claude`-нода не підтримує багатокроковий діалог

**Статус:** Відкритий  
**Пріоритет:** Критичний  
**Виявлено при:** Тестування Bot 1.1

**Опис:**  
Зараз `claude`-нода працює тільки як одноразовий виклик: надіслала одну відповідь → передала управління далі по воронці. Але більшість ботів курсу потребують повноцінного діалогу: студент відповідає кілька разів, Claude обробляє кожну відповідь, і лише після виконання умови — переходимо далі.

**Пропозиція: параметр `mode` в claude-ноді**

Додати два режими роботи ноди:

---

### `mode: "single"` (поточна поведінка, за замовчуванням)

Один виклик Claude → результат в `outputVar` → перехід до наступної ноди.

**Використання:** генерація документу на основі готових даних, класифікація, одноразовий аналіз.

```json
{
  "type": "claude",
  "data": {
    "mode": "single",
    "systemPrompt": "...",
    "outputVar": "context.result"
  }
}
```

---

### `mode: "dialog"` (новий режим)

Нода залишається активною. Кожне повідомлення студента → новий виклик Claude з повною `conversationHistory` → відповідь студенту → чекати наступного повідомлення.

Вихід з ноди — тільки коли виконується `exitCondition`.

```json
{
  "type": "claude",
  "data": {
    "mode": "dialog",
    "systemPrompt": "...",
    "outputVar": "context.result",
    "exitCondition": "json_output"
  }
}
```

**Підтримувані значення `exitCondition`:**

| Значення | Умова виходу |
|----------|--------------|
| `"json_output"` | Остання відповідь Claude є валідним JSON — зберегти в `outputVar` і перейти далі |
| `"keyword: DONE"` | Відповідь Claude містить вказане ключове слово (налаштовується) |
| `"user_confirms"` | Студент надіслав підтвердження: «так», «вірно», «ок», «гаразд» (після чого Claude робить фінальний виклик і генерує результат) |
| `"markdown_output"` | Остання відповідь Claude містить Markdown-блок (``` або # заголовок) |

**Логіка виходу при `json_output`:**
```
1. Claude відповідає
2. Runtime перевіряє: чи є у відповіді валідний JSON?
3. Якщо так → парсить JSON, записує в outputVar → переходить до наступної ноди
4. Якщо ні → відправляє відповідь студенту, чекає наступного повідомлення
```

---

**Яких ботів курсу стосується:**

| Бот | Потрібний mode |
|-----|----------------|
| 1.1 Onboarding | `dialog` + `exitCondition: "json_output"` |
| 1.2 Business Process | `dialog` + `exitCondition: "json_output"` |
| 2.1 Articles | `dialog` + `exitCondition: "json_output"` |
| 3.3 Diagnostics | `dialog` + `exitCondition: "markdown_output"` |
| Всі інші з claude-нодою | потребує перевірки після реалізації |

## BUG-004 · `saveFile` зберігає неправильне значення змінної

**Статус:** Відкритий  
**Пріоритет:** Високий  
**Залежить від:** BUG-003

**Симптоми:**  
`saveFile` нода з `contentVar: "context.onboarding_result"` зберегла не JSON з даними студента, а перше питання Claude:
```
"onboarding_result": "Привіт! 👋 Чудово, що ти тут!\n\nДавай познайомимось. Як тебе звати?"
```

**Очікуваний вміст файлу:**
```json
{
  "name": "...",
  "role": "...",
  "company_description": "...",
  "main_problem": "..."
}
```

**Примітка:**  
Скоріш за все є наслідком BUG-003 — `outputVar` містить останню відповідь Claude (перше питання діалогу), бо діалог не дійшов до фінального JSON. Після фіксу BUG-003 перевірити окремо чи правильно `outputVar` → `context.*` → `saveFile` маппиться.
